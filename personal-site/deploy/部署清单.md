# 今日食签 v0.5 — 部署清单

整套脚本都在 `personal-site/deploy/`，只依赖 node ≥ 18、npm、curl。

## 一、一次部署要做的四件事

```bash
cd personal-site/deploy

# 1) 预检（30 秒，不花钱，先把坑扫一遍）
bash preflight.sh

# 2) 填配置
cp deploy.env.example deploy.env
#   必填两个：CLOUDFLARE_API_TOKEN、ZHIPU_API_KEY

# 3) 部署后端（幂等，可重复执行）
bash deploy.sh

# 4) 把 Worker 地址回填前端
cp frontend.conf.example frontend.conf
#   把 deploy.sh 打出的地址填进 WORKER_URL
bash frontend.sh
```

## 二、要准备的东西

| 项 | 用途 | 哪里拿 |
|---|---|---|
| Cloudflare API Token | 部署 Worker、读写 KV | https://dash.cloudflare.com/profile/api-tokens （见下方权限） |
| 智谱 API Key | 对话模型（免费） | https://bigmodel.cn/usercenter/apikeys |
| DeepSeek API Key | 可选，开了才有联网搜索 | https://platform.deepseek.com/api_keys |
| 美团 token | 可选，到店团购 | 美团 App 扫码授权（约 30 天） |

**Cloudflare Token 权限**（Create Token → Custom token，三项都要给）：

- Account · Workers Scripts · Edit
- Account · Workers KV Storage · Edit
- Account · Account Settings · Read

Account Resources 选你自己的账号。

## 三、deploy.sh 做了什么

1. 校验 token 有效性
2. 拿 Account ID（deploy.env 没填就自动从 API 取第一个）
3. **KV 幂等**：以 `wrangler.toml` 里已填的 id 为准验证存在性，不存在才去找、最后才新建
4. 逐个写 secret（值为空的跳过）
5. 把 `AI_PROVIDER` 写回 `wrangler.toml` 的 `[vars]`，保证两处一致
6. `wrangler deploy`
7. 调 `/api/v1/health` 自检并打印配置状态

> KV 幂等这一步很关键：早期版本按 `title === "USAGE"` 查找，
> 而实际命名空间叫 `spend`，永远匹配不上 → 每次部署都新建一个命名空间、
> 把绑定 id 换掉，历史用量和限流状态全部归零。现在以 toml 里的 id 为准。

## 四、切换对话模型

只改 `deploy.env` 一处：

```bash
AI_PROVIDER=deepseek   # 默认 zhipu
```

DEEPSEEK_API_KEY 也填上，然后重跑 `bash deploy.sh`。
模型名会自动纠正（防止切了厂商忘改 `MODEL` 拿到 400）。

## 五、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `Token 无效或已过期` | 权限没给全，或 token 被删 | 重新建 token，三项权限都要 |
| `找不到后端目录` | 不在 `deploy/` 下执行 | `cd personal-site/deploy` 后再跑 |
| `/health` 返回 `platforms.ai: "missing_zhipu_key"` | secret 没写进去 | 确认 `deploy.env` 里 `ZHIPU_API_KEY` 非空后重跑 |
| `/chat` 返回 `UPSTREAM_BUSY` | 智谱免费档并发限制（约 1 路） | 正常现象，已做 0/1.2/2.6s 退避重试；前端会自动降级 |
| 浏览器控制台报 CORS | `ALLOWED_ORIGINS` 不含站点域名 | 改 `wrangler.toml` 的 `ALLOWED_ORIGINS` 后重新部署 |
| 自检拿不到响应 | 本机到 `workers.dev` 不通 | 用浏览器直接打开 `/api/v1/health` |

## 六、回滚

Cloudflare 控制台 → Workers & Pages → `shiqian-agent` → Deployments →
选历史版本 → Rollback。命令行没有一键回滚，但重跑 `deploy.sh` 会推到新版本。

## 七、本地开发

```bash
cd personal-site/backend
npm install
npx wrangler dev            # 默认 http://localhost:8787
node --test test/unit.test.mjs
```

本地调试密钥可用 `backend/.dev.vars`（已 gitignore）：

```
ZHIPU_API_KEY=xxx
```

## 八、CI

`.github/workflows/backend-ci.yml`：在 `main` 分支、且改动
`personal-site/backend/**` 或 `personal-site/app/**` 时跑语法检查与 28 项单测。

`.github/workflows/deploy-personal-site.yml`：推 `main` 时自动部署前端到 Cloudflare Pages，
需先在仓库 Secrets 里配 `CLOUDFLARE_API_TOKEN` 与 `CLOUDFLARE_ACCOUNT_ID`。
